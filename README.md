# Афиша рядом

Бот и мини-приложение в MAX для поиска событий рядом с небольшими городами и сёлами. Пользователь выбирает населённый пункт и интересы, открывает ленту, сохраняет событие и получает напоминание. Организатор создаёт событие из формы или текста, после чего оно проходит автоматическую модерацию по правилам. Сайт работает и без MAX: афиша открыта без входа, «Пойду» доступно гостю, а вход кодом через бота переносит гостевые данные в MAX-аккаунт.

## Архитектура

FastAPI API и webhook бота, arq worker, PostgreSQL 16 + PostGIS, Redis 7, React 18 + TypeScript мини-приложение за nginx, Caddy в production. Изменения сущностей пишутся в `audit_log`; официальные и community события выдаются раздельно.

## Запуск

Требуется Docker Compose v2.24+:

```bash
cp .env.example .env
docker compose up --build
```

Мини-приложение: `http://localhost:8080`, API: `http://localhost:8000`; PostgreSQL и Redis доступны только внутри Compose. `make migrate` применяет миграции, `make seed` загружает демо-набор. Для разработки нужны Python 3.12 + uv и Node.js 22; зависимости зафиксированы в `backend/uv.lock` и `frontend/package-lock.json`.

## Переменные окружения

Полный список в [`.env.example`](.env.example). Секреты (`MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET`, `JWT_SECRET`, пароли БД) задаются только в `.env`. `MAX_BOT_USERNAME` нужен для диплинков, в том числе для входа на сайте кодом. `GUEST_JWT_TTL_DAYS` — срок гостевого токена (30 дней). `SEED_DEMO=1` загружает демо-набор при старте. `DEV_AUTH=1` допустим только локально. `REVIEW_MODE=1` включает `/api/v1/auth/review-login`; JSON `REVIEW_ACCOUNTS` задаётся человеком, в репозитории паролей нет.

## Внешние сервисы

Единственный внешний сервис — MAX Bot API (бот, webhook, вход на сайте кодом). LLM, DaData, геокодеры и сторонние афиши не используются: разбор поисковой фразы, черновик из текста анонса, модерация и проверка ИНН (формат и контрольная сумма) работают на детерминированных правилах (`backend/app/parsing/`, `backend/app/moderation/`). Без токена MAX сайт и API работают полностью, кроме бота и входа через MAX.

## Веб-режим без MAX

- `GET /api/v1/events`, `/localities`, `/categories`, `POST /search/parse` — без токена.
- `POST /api/v1/auth/guest` — гостевой токен на 30 дней (не больше 5 в час с одного IP); гостю не приходят уведомления в бот.
- `POST /api/v1/auth/web-code` → `{code, deeplink, expires_in}`; пользователь открывает `https://max.ru/<бот>?start=login_<code>` и подтверждает вход кнопкой в боте; сайт опрашивает `POST /api/v1/auth/web-code/poll` (202 — ждём, 200 — токен, 410 — код истёк или уже использован). Код живёт 5 минут и одноразовый.

## Данные и резервные копии

Тестовые данные сгенерированы и помечены: реальные населённые пункты и площадки (`data/seed/`: ~30 н.п. Новгородской области, Татарстана и Ярославской области, ~80 площадок, ~40 организаций) и вымышленные события (~400 на 3–4 недели вперёд), которые строит детерминированный генератор `backend/app/demo/` с фиксированным seed. У всех событий `source=demo`/`trust_tier=demo` и видимая плашка «Демо-данные». `make seed` идемпотентен: повторный запуск сдвигает сеансы к текущей дате, сохраняя «Пойду»; события непроверенных организаций попадают только в ленту сообщества. Резервная копия: `DATABASE_URL=... BACKUP_DIR=./backups make backup`; хранятся последние 7 дней.

### Справочник населённых пунктов

`data/seed/localities_ru.csv.gz` — ~146 тыс. населённых пунктов России (город, пгт, посёлок, село, деревня) с районом, регионом, координатами, населением и часовым поясом (по региону). Источник — OpenStreetMap: **© участники OpenStreetMap, [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/)**, openstreetmap.org/copyright; атрибуция также на странице `/legal/data`. Файл собирает человек один раз: `uv run tools/build_localities.py russia-latest.osm.pbf data/seed/localities_ru.csv.gz` (выгрузка Geofabrik, ~2 минуты); сборка детерминирована. `python -m app.seed` (и старт `migrate`) загружает его всегда, независимо от `SEED_DEMO`: COPY во временную таблицу и upsert по `key`, повторно — только при изменении файла (≈15 с на пустой БД). Демо-НП без `key` привязываются к одноимённой строке справочника поблизости, их связи сохраняются. Поиск `GET /api/v1/localities?q=`: точное имя > начало имени > похожесть (pg_trgm) > население, ё = е, дефис = пробел, до 10 вариантов с районом и регионом.

## Сценарий проверки

1. Запусти Compose и проверь `/health`, `/ready`.
2. Открой `http://localhost:8080`: лента видна без входа. Войди гостем или через `DEV_AUTH=1`, прими условия, выбери населённый пункт и интересы.
3. Проверь вкладки ленты, радиус, дату, цену, Пушкинскую карту, карточку и «Пойду».
4. Открой настройки и удаление данных; создай черновик организатора и отправь на проверку.
5. Для API используй [DATA-API.yaml](DATA-API.yaml), для ручного прогона — [docs/QA_CHECKLIST.md](docs/QA_CHECKLIST.md).

Ошибки имеют `error.code/message/details`, сетевые сбои показывают «Повторить», бот отвечает fallback-текстом, события сообщества не попадают в официальную ленту.

## Проверки и материалы сдачи

```bash
make lint
make test
make openapi
cd backend && uv run pip-audit
cd frontend && npm audit --audit-level=high
```

`openapi.yaml` и `DATA-API.yaml` описывают API. Адрес production API, токен бота и review-пароли передаются жюри отдельно.

## Ограничения

Продакшен требует публичного HTTPS и токена MAX. Геолокация в WebView может быть недоступна, поэтому есть выбор населённого пункта. Продажа билетов, встроенная карта, парсинг сайтов, импорт из сторонних афиш и Kubernetes не входят в MVP (импорт — точка масштабирования). Адреса демо-площадок приблизительные.

## Возможности MAX

Используются `startapp` диплинки, `request_geo_location`, проверяемый `request_contact`, `shareMaxContent` с копированием ссылки, BackButton, haptics и уведомления/дайджест от бота.
